# with-ai

폰에서 프로젝트 계획과 작업 진행 상황을 기록하고, 코드 제작 AI에 전달할 요청문을 준비하는 한국어 웹앱입니다.

## 실행

Node.js 22 LTS 이상과 npm을 사용하세요. 환경 변수나 API 키는 필요하지 않습니다.

```bash
npm ci
npm run dev
```

브라우저에서 <http://localhost:3000>을 엽니다.

프로덕션 실행:

```bash
npm run build
npm start
```

## 구현 기능

- 프로젝트 생성·수정·삭제, 삭제 확인, 첫 사용 안내
- 저장 전 프로젝트의 기기 내 초안 저장, 비정상 종료 후 생성·수정 내용 복구 및 목록 표시
- 작업 카드 생성·수정·삭제 및 제목·설명·요구사항·완료 조건·상태·생성/수정 시각 저장
- 저장 전 작업 카드의 기기 내 초안 저장, 비정상 종료 후 생성·수정 내용 복구 및 목록 표시
- 상태 이름과 색상을 함께 표시하고 상태별 카드 개수를 표시하는 필터
- 카드별 중요 작업 표시와 기본 순서·중요 작업 먼저·최근 수정 순 정렬
- 제목·설명·요구사항·완료 조건·진행 메모 검색, 상태 필터와 함께 검색 및 초기화
- 카드 상세에서 직접 작성하는 최신 진행 메모: 한 일, 막힌 점, 다음 할 일, 메모 수정 시각
- 메모 내용을 바꿔 저장할 때 이전 저장본을 이력으로 보관하고 카드 상세에서 펼쳐 확인
- 이전 진행 메모의 한 일·막힌 점·다음 할 일 검색, 선택한 기록을 현재 메모 초안으로 불러오기
- 저장 전 진행 메모의 기기 내 임시 저장, 비정상 종료 후 복구 및 카드 목록 표시
- 완료 개수 / 계산 대상 개수와 진행률 표시
- 프로젝트와 카드 정보를 텍스트 양식에 넣는 AI 작업 요청문 생성·편집·복사
- 수정 중인 AI 요청문의 기기 내 초안 저장, 비정상 종료 후 복구 및 카드 목록 표시
- 복사 성공/실패 안내, 실패 시 자동 전체 선택과 직접 복사 안내
- 실제 파일 용량 사전 안내와 크기를 줄인 JSON 내보내기, 형식 검증·교체 확인·교체 직전 자동 복구 지점을 거치는 가져오기
- 현재 데이터·초안·복구본을 바꾸지 않고 교체 전 데이터를 별도 JSON으로 내보내기
- 교체 전 복구본에서 프로젝트 하나를 골라 현재 데이터·초안·복구본을 유지하며 별도 프로젝트로 추가
- 지원하는 모바일·데스크톱 브라우저에서 홈 화면 또는 앱으로 설치하고 준비된 화면을 오프라인에서 다시 여는 PWA
- 모바일 세로 카드 목록과 하단 주요 작업 버튼, PC 프로젝트 사이드바
- 입력 이름·필수 값 오류 표시, 키보드 포커스, 네이티브 모달과 화면 읽기 안내
- 저장 공간/권한 오류 안내 및 실패한 입력 유지, 손상 데이터의 원본을 유지하고 백업 복구 안내
- 프로젝트·카드·진행 메모·요청문의 저장/복사하지 않은 수정 내용이 있으면 닫기·취소·화면 전환 전 확인
- 다른 탭에서 프로젝트·카드·진행 메모를 먼저 저장하면 필드별 변경 병합, 같은 항목 충돌 안내 및 재저장 확인

### 작업 상태

| 상태          | 색상   | 의미                                        | 진행률 포함 |
| ------------- | ------ | ------------------------------------------- | ----------- |
| 할 일         | 회색   | 앞으로 시작할 작업                          | 포함        |
| 진행 중       | 노란색 | 현재 진행하는 작업                          | 포함        |
| 완료          | 초록색 | 완료 조건을 충족한 작업                     | 포함        |
| 안 할 거      | 검은색 | 이번 프로젝트에서는 진행하지 않기로 한 작업 | 제외        |
| 폐기 아이디어 | 빨간색 | 검토 후 아이디어 자체를 폐기한 작업         | 제외        |

진행률은 `완료 ÷ (할 일 + 진행 중 + 완료) × 100`이며 표시할 때 정수로 반올림합니다. 계산 대상이 0개이면 0%입니다. 검은색 카드에는 밝은 글자를 사용합니다.

## 저장 방식과 한계

- 로그인과 서버 저장 없이 `localStorage`의 `with-ai:data:v1`에 버전 1 데이터를 저장합니다. 내부 `importRecovery` 필드에 최근 복구본을 함께 보관해 데이터와 복구본을 한 번의 저장으로 갱신합니다. 이전 별도 키의 복구본도 읽으며, 저장 성공 후 함께 저장하는 형식으로 옮깁니다. JSON 내보내기는 버전 1 프로젝트·카드·중요 표시·메모와 메모 이력을 포함하고 내부 복구본은 제외합니다.
- 저장은 명시적인 저장 버튼을 눌렀을 때 이루어집니다. 카드 정보와 진행 메모는 별도로 저장합니다. 저장하지 않은 변경이 있으면 닫기·취소·Esc 및 수정/삭제 화면 이동 전에 확인합니다. **계속 작성**은 입력을 유지하고 **버리고 이동**은 현재 편집만 버립니다. 저장 실패 후에도 확인이 유지됩니다.
- 수정한 AI 요청문은 복사에 성공하기 전까지 같은 방식으로 보호합니다. 복사한 뒤 다시 수정하면 다시 확인하며, 전체 선택이나 복사 실패는 복사 성공으로 간주하지 않습니다. 요청문 수정 내용은 영구 앱 데이터로 확정 저장하지 않습니다.
- 저장/복사하지 않은 수정 내용이 있으면 지원하는 브라우저에서 새로고침·탭 닫기·페이지 이탈 시 브라우저 기본 확인창을 표시합니다.
- 새 프로젝트와 기존 프로젝트 수정 내용은 입력할 때 프로젝트별 별도 `localStorage` 초안으로 현재 기기에 임시 저장합니다. 종료 후에는 **작성 중 프로젝트 계속** 버튼이나 프로젝트 목록의 **초안**, 현재 프로젝트의 **수정 초안 있음** 표시로 돌아가 이름과 설명을 복구할 수 있습니다. 프로젝트 저장이나 **버리고 이동**, 프로젝트 삭제, 백업 데이터 교체 시 관련 초안을 정리합니다.
- 기존 프로젝트 초안은 이름과 설명이 같은 저장본에만 복구합니다. 다른 탭에서 프로젝트 정보가 바뀌면 이전 초안이 새 저장본을 덮어쓰지 않습니다. 초안 저장에 실패해도 화면의 입력은 유지하고 오류를 알립니다.
- 새 작업 카드와 기존 카드 수정 내용은 입력할 때 프로젝트·카드별 별도 `localStorage` 초안으로 현재 기기에 임시 저장합니다. 종료 후에는 **작성 중 카드 계속** 버튼이나 카드 목록의 **카드 수정 초안 있음** 표시로 돌아가 모든 입력 필드와 상태를 복구할 수 있습니다. 카드 저장이나 **버리고 이동**, 카드·프로젝트 삭제, 백업 데이터 교체 시 관련 초안을 정리합니다.
- 기존 카드의 초안은 제목·설명·요구사항·완료 조건·상태가 같은 저장본에만 복구합니다. 다른 탭에서 카드 정보가 바뀌면 이전 초안이 새 저장본을 덮어쓰지 않습니다. 초안 저장에 실패해도 화면의 입력은 유지하고 오류를 알립니다.
- 진행 메모는 입력할 때 별도의 `localStorage` 초안으로 현재 기기에 임시 저장합니다. 탭이나 브라우저가 확인 없이 종료돼도 같은 카드에서 다시 열면 복구하며, 카드 목록에 **임시 메모 있음**으로 표시합니다. 메모 저장이나 **버리고 이동**, 카드·프로젝트 삭제, 백업 데이터 교체 시 관련 초안을 정리합니다.
- 임시 메모는 같은 카드의 최신 저장본을 기준으로만 복구해 다른 탭에서 새 메모가 저장된 경우 오래된 초안을 덮어쓰지 않습니다. 임시 저장에 실패하면 입력은 화면에 유지하고 오류를 알립니다.
- 진행 메모의 내용을 바꿔 저장하면 이전 저장본의 세 필드와 저장 시각을 카드의 선택 필드 `noteHistory`에 보관합니다. 첫 입력 전 빈 메모와 같은 내용의 재저장은 이력을 추가하지 않습니다. 현재 메모를 빈 내용으로 바꿔도 이전 내용은 이력에 남습니다. 저장 실패나 충돌 확인 단계에서는 현재 저장본과 이력을 함께 유지합니다.
- 카드 상세의 **이전 메모 N개**에서 최근 교체된 순서로 조회하고 한 일·막힌 점·다음 할 일을 검색합니다. 검색 결과도 10개씩 더 볼 수 있으며 검색하거나 펼쳐 보는 동작은 현재 메모·초안을 바꾸지 않습니다. 이력은 자동 삭제하지 않고, 저장 공간이 부족하면 기존처럼 저장을 중단하고 입력을 유지합니다. 이 기능 도입 전에 덮어쓴 내용은 복구할 수 없습니다.
- 이전 기록의 **이 기록을 현재 메모로 불러오기**는 세 필드를 현재 입력에 복사하고 기존 진행 메모 초안과 같은 경로에 임시 저장합니다. 확정 데이터와 원본 이력은 **메모 저장** 전까지 바뀌지 않으며 새로고침 뒤에도 이어 쓸 수 있습니다. 이미 저장하지 않은 입력이 있으면 교체 전에 확인하고, 취소하면 기존 입력을 유지합니다.
- 작업 카드 목록 검색과 AI 요청문에는 최신 진행 메모만 사용합니다. 이전 기록을 불러온 뒤 메모를 먼저 저장해야 목록 검색과 AI 요청문에 반영됩니다.
- 수정한 AI 요청문은 프로젝트·카드별 별도 `localStorage` 초안으로 현재 기기에 임시 저장합니다. 확인 없이 종료돼도 카드 목록의 **요청문 초안 있음**과 카드 상세의 **작성 중 요청문 계속**으로 돌아가 편집 내용을 복구할 수 있습니다. 복사 성공, 생성 원문으로 되돌리기, **버리고 이동**, 관련 프로젝트·카드·메모 수정이나 삭제, 백업 데이터 교체 시 초안을 정리합니다.
- 요청문 초안은 편집을 시작할 때 생성된 원문과 현재 저장 데이터로 다시 만든 원문이 정확히 같을 때만 복구합니다. 다른 탭에서 프로젝트·카드·메모가 바뀌면 오래된 초안을 새 요청문 위에 덮어쓰지 않습니다. 초안 저장에 실패해도 화면의 입력과 직접 복사 경로를 유지하고 오류를 알립니다.
- 데이터는 **현재 기기·브라우저·사이트 주소에만** 존재합니다. 다른 브라우저나 기기, 개발 서버와 배포 사이트 사이에 자동 동기화되지 않습니다.
- 브라우저 데이터 삭제, 시크릿 창 종료, 저장소 정리 등으로 기록이 사라질 수 있습니다. 중요한 기록은 JSON으로 백업하세요.
- JSON 가져오기 직전의 확정 데이터는 복구 지점으로 현재 브라우저에 자동 보관합니다. 최근 1개만 설정에서 확인할 수 있고 전체 데이터 복구에 성공하면 해제됩니다. **프로젝트 선택 복구**는 현재 데이터와 작성 중 초안을 유지한 채 고른 프로젝트의 별도 복사본을 추가하고 복구 지점도 남겨 둡니다. 가져오기 저장에 실패하면 현재 데이터와 이전 복구본을 모두 유지하며 재시도할 수 있습니다. 복구 저장 실패도 현재 데이터와 복구본을 유지합니다. 저장하지 않은 초안은 복구 지점 자체에는 포함하지 않습니다.
- 브라우저 저장 공간이 부족하거나 저장 권한이 차단되면 저장에 실패할 수 있습니다. 실패한 저장은 성공으로 표시하지 않으며 편집 화면을 유지합니다.
- 같은 사이트의 다른 탭에서 바뀐 데이터는 `storage` 이벤트로 갱신합니다. 프로젝트·카드·진행 메모를 편집하는 동안 다른 탭이 먼저 저장하면 곧바로 덮어쓰지 않습니다. 서로 다른 필드의 변경은 합치고, 같은 필드를 다르게 수정한 경우 현재 탭의 입력을 보존해 충돌 항목을 알립니다. 병합 결과를 확인한 뒤 **확인 후 다시 저장**을 눌러야 확정됩니다. 아직 읽지 않은 외부 변경도 저장 단계에서 감지해 중단합니다.
- 복사 기능은 HTTPS 또는 localhost 및 브라우저 클립보드 권한이 필요할 수 있습니다. 실패 시 선택된 텍스트를 길게 누르거나 Ctrl+C / ⌘C로 직접 복사할 수 있습니다.
- 지원하는 브라우저에서는 HTTPS 또는 localhost에서 브라우저 메뉴의 **앱 설치**나 **홈 화면에 추가**로 설치할 수 있습니다. 설치하면 앱 이름과 전용 아이콘으로 독립 창에서 열립니다.
- 프로덕션 앱을 온라인에서 한 번 열어 서비스 워커 준비가 끝나면 앱 화면과 실행에 필요한 같은 출처의 정적 파일을 브라우저 캐시에 보관합니다. 이후에는 네트워크가 없어도 앱을 다시 열거나 새로고침해 현재 브라우저의 프로젝트를 이어 볼 수 있습니다. 개발 중 오래된 파일이 남지 않도록 `npm run dev`에서는 서비스 워커를 등록하지 않습니다.
- 온라인으로 앱을 다시 열면 새 화면이 참조하는 정적 파일을 먼저 모두 확보한 뒤 오프라인 시작 화면을 교체합니다. 갱신 중 연결이 끊기거나 파일 하나라도 준비하지 못하면 마지막 정상 앱 셸을 유지하며, 더 이상 쓰지 않는 이전 Next.js 정적 파일과 이전 버전 앱 셸 캐시는 준비가 끝난 뒤 정리합니다.
- 앱 셸 캐시는 화면 코드·스타일·매니페스트·아이콘만 담고 `localStorage`의 프로젝트·카드·메모는 복제하지 않습니다. 처음 방문하는 기기, 브라우저 데이터나 사이트 저장 공간을 지운 뒤, 서비스 워커를 지원하지 않는 브라우저에서는 먼저 네트워크가 필요합니다. 배포 환경에서는 HTTPS가 필요합니다.

### JSON 백업

설정의 **JSON 내보내기**에서 모든 프로젝트·카드·저장한 메모를 내려받습니다. 설정에는 내보낼 실제 UTF-8 JSON 파일의 예상 크기와 5MB 가져오기 한도를 함께 표시하며, 한도의 80%부터 미리 경고합니다. 내보내기는 불필요한 들여쓰기 없이 저장해 같은 내용의 파일 크기를 줄입니다. 아직 저장하지 않은 프로젝트·작업 카드·진행 메모·AI 요청문 초안과 내부 복구본은 백업에 포함하지 않습니다. **JSON 가져오기**는 파일을 읽고 버전·필드 타입·필수 이름·상태·날짜·중복 ID를 검증한 뒤 교체할 프로젝트와 카드 개수 및 파일 크기를 안내합니다. **데이터 교체**를 누르면 가져온 데이터와 교체 직전의 확정 복구본을 함께 저장합니다. 저장에 실패하면 현재 데이터와 이전 복구본을 모두 유지하며 가져오기를 중단합니다. 최근 복구 지점은 설정에서 시각과 개수를 확인한 뒤 **교체 전 데이터 복구**로 전부 되돌리거나 **프로젝트 선택 복구**로 프로젝트 하나만 현재 데이터에 추가할 수 있습니다. 선택 복구는 프로젝트·카드 ID를 새로 만들어 같은 이름이나 과거 ID가 겹쳐도 별도 항목으로 저장하며 메모 이력·중요 표시·날짜를 보존합니다. 전체 프로젝트 1,000개·카드 10,000개 한도를 넘기는 추가는 중단합니다. 복구 확인 중 다른 탭이 복구 지점을 바꾸면 오래된 확인으로 저장하지 않고 설정에서 다시 확인하도록 안내합니다. 잘못된 파일과 취소는 기존 데이터를 변경하지 않습니다.

설정의 **복구본 JSON 내보내기**는 교체 전 프로젝트·카드·저장한 메모만 별도의 버전 1 JSON 파일로 내려받습니다. 현재 데이터·작성 중인 초안·기기에 보관된 복구본은 바꾸거나 삭제하지 않습니다. 파일 이름은 `with-ai-recovery-보관시각.json`으로 일반 백업과 구분하며 보관시각은 UTC입니다. 다운로드한 파일은 같은 **JSON 가져오기** 경로로 사용할 수 있습니다. 다음 가져오기로 복구본이 교체되기 전에 별도 파일로 보관하거나 현재 데이터와 이전 데이터를 각각 내보낼 때 사용하세요. 현재 데이터가 손상돼 일반 내보내기를 사용할 수 없어도 정상 복구본은 내보낼 수 있습니다.

내보내기 안내는 브라우저에 다운로드를 요청했다는 뜻이며 실제 파일 저장 완료를 보장하지 않습니다. 다운로드 목록에서 파일이 저장됐는지 확인해 주세요. 다운로드 시작 오류는 화면에 알리고 저장 데이터는 그대로 유지하므로 다시 시도할 수 있습니다.

가져오기 제한: 최대 5MB, 프로젝트 1,000개, 전체 카드 10,000개. 프로젝트 이름은 100자, 카드 제목은 120자, 설명·요구사항·완료 조건·각 메모는 10,000자까지입니다. 알 수 없는 추가 필드는 가져올 때 생략합니다. JSON 파일에는 사용자가 쓴 내용이 포함되므로 파일 보관 위치를 직접 관리하세요.

메모 이력도 일반 JSON 백업·복구본 내보내기·가져오기·교체 전 자동 복구에 포함합니다. `noteHistory`가 없는 기존 버전 1 백업도 계속 사용할 수 있습니다. 이력이 있으면 배열·각 메모의 필드 타입·길이·날짜를 모두 검증하며 잘못된 이력을 조용히 버리고 가져오지 않습니다. 이력 기능이 없는 구버전 앱은 이 필드를 무시하므로 이력을 보존하려면 최신 앱에서 백업을 사용하세요. 초안은 여전히 백업과 메모 이력에 포함하지 않습니다.
