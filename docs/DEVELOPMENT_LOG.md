# 개발 기록

프로젝트 계획·작업 카드·진행 메모·AI 작업 요청문을 폰에서 편하게 관리하는 목적에 맞춰 개선합니다. 후속 작업은 최신 코드와 이 기록을 확인한 뒤 선택합니다.

## 2026-10-10 — 작업 카드 검색

카드가 늘어났을 때 상태 필터만으로 원하는 작업을 찾기 어려워 검색을 추가했습니다.

- 제목, 설명, 요구사항, 완료 조건, 진행 메모의 한 일·막힌 점·다음 할 일을 검색합니다.
- 앞뒤 공백과 영문 대소문자를 무시하며 현재 상태 필터와 함께 적용합니다.
- 검색 결과 개수, 결과 없음 안내, 검색어 지우기, 검색·필터 초기화를 제공합니다.
- 프로젝트 선택·삭제 및 백업 가져오기 시 검색어를 초기화합니다.
- 검색은 저장 데이터를 변경하지 않으며 프로젝트 전체의 진행률과 상태별 집계를 유지합니다.

검증: 타입 검사, ESLint, 모델 테스트 4개, 프로덕션 빌드 통과. 브라우저 시나리오 5개 통과(신규 검색 1개와 기존 4개). 검색 중 데이터 보존, 상태 조합, 공백·영문 대소문자 처리, 390px/1440px 화면 넘침을 확인했습니다.

실행 환경: 오프라인 패키지 설치는 캐시 누락으로 완료되지 않아 동일한 lockfile로 설치돼 있던 의존성을 사용했습니다. 준비된 Chromium으로 검사했으며, 처음 브라우저 프로세스 종료로 실행되지 못한 기존 시나리오 2개는 임시 실행 옵션을 수정한 뒤 재실행해 통과했습니다. 이 환경용 실행 설정은 저장소에 포함하지 않습니다.

## 2026-10-11 — 저장하지 않은 편집 내용 확인

최신 `dev`의 `e06a01b`를 별도 디렉터리에 가져와 확인했습니다. `main`은 `80b34f8`이며 열린 PR·이슈는 없었습니다. 프로젝트 내용을 입력한 뒤 닫으면 확인 없이 편집 화면이 사라지는 문제를 브라우저 테스트로 재현해 우선 개선했습니다.

- 프로젝트·작업 카드·진행 메모의 변경이 있으면 닫기·취소·Esc 및 수정/삭제 화면 전환 전에 확인합니다. 확인 중에도 원래 편집 화면을 유지하며, **계속 작성** 또는 확인창 닫기는 입력을 보존합니다.
- **버리고 이동**을 눌렀을 때만 현재 편집을 버리고 요청한 화면으로 이동합니다. 삭제 화면에서는 기존 삭제 확인을 별도로 거칩니다.
- 원래 값으로 되돌렸거나 저장에 성공했으면 다시 확인하지 않습니다. 저장 실패 시에는 보호를 유지합니다.
- 수정한 AI 요청문은 복사에 성공한 내용과 비교합니다. 복사 실패·전체 선택은 보호를 해제하지 않으며, 복사 후 재수정하면 다시 확인합니다.
- 변경이 있을 때만 `beforeunload`를 구독해 지원하는 브라우저의 새로고침·페이지 이탈 확인을 요청합니다.
- 확인창은 **계속 작성**에 초기 포커스를 두고, 닫힌 뒤 원래 버튼으로 포커스를 돌립니다. 겹친 모달을 함께 닫아도 본문 스크롤 잠금이 남지 않도록 처리했습니다.
- 저장 데이터 구조·상태 색상·버전 1 JSON 백업·요청문 생성 규칙은 유지했습니다.

검증: `npm run typecheck`, `npm run lint`, `npm test`(모델 4개), `npm run build` 통과. Playwright 시나리오 10개(기존 5개, 신규 5개) 통과. 닫기/취소/Esc, 수정·삭제 전환, 원래 값으로 되돌리기, 저장 실패 후 입력 유지, 복사 실패와 복사 후 재수정, 실제 새로고침 확인 취소 및 저장 후 확인 해제를 검사했습니다. 확인창의 포커스·스크롤 복원, 320px/390px/1440px 가로 넘침과 화면 캡처를 확인했으며 화면 점검 중 브라우저 오류는 없었습니다.

실행 환경: 저장소의 lockfile과 기존 설치 기록의 버전·무결성 값이 일치하는 372개 패키지를 확인한 뒤 의존성을 별도 작업 디렉터리에 복사했습니다. 프로덕션 서버와 Chromium 153으로 검증했고 환경용 Playwright 설정 및 한국어 화면 점검 폰트는 커밋에 포함하지 않았습니다. 검증 중 발견한 확인창 초기 포커스 문제를 수정했으며, 새로고침 취소 테스트가 취소된 탐색 완료를 계속 기다리던 부분을 바로잡은 뒤 전체 브라우저 시나리오를 통과했습니다.

남은 한계: 자동 임시 저장은 아닙니다. 모바일 브라우저 강제 종료 등 `beforeunload`가 발생하지 않는 상황의 입력 복원과 다른 탭의 동시 수정/삭제에 대한 초안 보존은 후속 작업입니다. 요청문 편집 내용은 앱에 저장하지 않습니다.

## 다음 개선 후보

현재 코드와 재현되는 문제를 먼저 확인하고, 아래 후보 중 효과가 큰 작은 작업을 선택합니다. 이미 해결된 후보를 반복 구현하지 않습니다.

- 강제 종료 후 초안 복원과 다른 탭의 수정·삭제 중 편집 내용 보존
- 진행 메모 이력 및 이전 기록 확인
- 카드 정렬, 중요한 작업 표시 등 목록 탐색 개선
- 백업 복원 흐름과 기존 데이터 보존 개선
- 설치·오프라인 사용성 및 모바일 접근성

새 의존성이나 저장 형식 변경이 필요하면 기존 기능 및 버전 1 백업과의 호환성을 먼저 확인합니다. 변경 내용, 실행한 검사, 실제 결과와 남은 작업을 이 기록에 이어 적습니다.
